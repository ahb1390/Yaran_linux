# انتشارها و مصنوعات CI

**English** ([releases.md](releases.md)) | فارسی ([releases.fa.md](releases.fa.md))

این سند روند ساخت ISOها، انتشار رسمی و روش دانلود، سرهم‌کردن و بررسی
صحت فایل‌های Yaran Linux را توضیح می‌دهد.

## سه سطحِ یک بیلد

| سطح | توضیح | کاربرد |
|---|---|---|
| **بیلد محلی** | ISO ساخته‌شده از یک commit مشخص | آزمایش و بررسی محلی |
| **مصنوع CI** | ISO اصلی به‌همراه checksum که از اجرای موفق workflow دریافت می‌شود | آزمایش؛ نه انتشار رسمی |
| **دارایی Release** | پارت‌های شماره‌گذاری‌شدهٔ ISO به‌همراه checksumها | کانال رسمی انتشار پروژه |

مصنوع‌های CI برای آزمایش هستند و ممکن است پس از مدت نگهداری GitHub منقضی شوند.
کانال دانلود عمومی و رسمی، صفحهٔ GitHub Releases است.

## روند ساخت CI

[workflow ساخت و اعتبارسنجی](https://github.com/ahb1390/Yaran_linux/actions/workflows/build.yml)
کد و manifestها را بررسی می‌کند و نسخه‌های تعریف‌شده در ماتریس انتشار را
می‌سازد. هر job لاگ ساخت و در صورت موفقیت ISO اصلی و checksum آن را به‌عنوان
artifact مربوط به CI بارگذاری می‌کند.

## روند انتشار رسمی و تقسیم ISOها

[workflow انتشار](https://github.com/ahb1390/Yaran_linux/actions/workflows/release.yml)
با **منتشر (Publish)** شدن یک GitHub Release اجرا می‌شود و نسخه‌های تعریف‌شده
در ماتریس را از commit مربوط به tag می‌سازد.

پیش از بارگذاری فایل‌ها در Release، هر ISO به پارت‌های شماره‌گذاری‌شده با
اندازهٔ حداکثر ۱۸۰۰ MiB تقسیم می‌شود تا هر فایل از محدودیت حجم تکی GitHub
کمتر باشد. فایل ISO اصلی به‌صورت یک فایل بزرگ در Release قرار نمی‌گیرد.

برای هر نسخه این فایل‌ها منتشر می‌شوند:

- `NAME.iso.part001`، `NAME.iso.part002` و پارت‌های بعدی در صورت نیاز؛
- `NAME.iso.sha256` — checksum فایل ISO نهایی پس از سرهم‌کردن؛
- `NAME.iso.parts.sha256` — checksum تمام پارت‌های دانلودشده.

تمام نسخه‌ها و پارت‌هایشان در همان Release قرار می‌گیرند. اگر ساخت ISO یا
آماده‌سازی پارت‌ها شکست بخورد، workflow باید با خطا متوقف شود.

## انتشار نسخه (ویژهٔ نگه‌دارندگان)

1. مطمئن شوید شاخهٔ هدف و تمام jobهای ساخت نسخه‌ها موفق هستند.
2. نسخهٔ درج‌شده در manifestها را با tag مورد نظر هماهنگ کنید.
3. یک GitHub Release با tag مانند `v2.0.1` بسازید و آن را **Publish** کنید.
   انتشار Draft باعث اجرای workflow نمی‌شود.
4. پس از پایان Release Build بررسی کنید پارت‌ها و هر دو فایل checksum برای
   تمام نسخه‌ها به همان Release اضافه شده باشند.
5. پیش از اعلام انتشار، دست‌کم یک ISO را سرهم و checksum آن را بررسی کنید.

## دانلود، سرهم‌کردن و بررسی صحت

تمام پارت‌های نسخهٔ موردنظر و هر دو فایل checksum آن را در یک پوشه دانلود
کنید. نام فایل‌ها را تغییر ندهید.

اگر مخزن را در اختیار دارید، از ریشهٔ پروژه اجرا کنید:

```bash
bash scripts/join-iso-parts.sh Yaran-2.0-amd64-minimal.iso
```

یا اگر همهٔ فایل‌ها در پوشهٔ فعلی هستند، دستی اجرا کنید:

```bash
sha256sum -c Yaran-2.0-amd64-minimal.iso.parts.sha256
cat Yaran-2.0-amd64-minimal.iso.part* > Yaran-2.0-amd64-minimal.iso
sha256sum -c Yaran-2.0-amd64-minimal.iso.sha256
```

بررسی اول صحت تمام پارت‌های دانلودشده را تأیید می‌کند. بررسی آخر مطمئن
می‌شود ISO بازسازی‌شده دقیقاً با فایل اصلی ساخته‌شده برابر است. اگر هرکدام
از بررسی‌ها خطا داد، فایل ناقص یا خراب را دوباره دریافت کنید.

برای دانلود artifactهای CI باید وارد GitHub شوید و از صفحهٔ اجرای workflow،
بخش **Artifacts** را باز کنید. فایل‌های Release از صفحهٔ عمومی همان انتشار
قابل دریافت هستند.
