# انتشارها و مصنوعات CI

**English** ([releases.md](releases.md)) | فارسی ([releases.fa.md](releases.fa.md))

این سند توضیح می‌دهد که تصاویر Yaran Linux چگونه توسط CI تولید می‌شوند،
تفاوت میان یک بیلد موفق، یک مصنوعِ (artifact) CI و یک انتشار رسمی چیست، و
چگونه چیزی را که دانلود می‌کنید راستی‌آزمایی کنید. این سند بازتاب‌دهندهٔ
workflowهای موجود در مسیر `.github/workflows/` در وضعیت کنونی آن‌هاست.

## سه سطحِ یک بیلد

| سطح | توضیح | سطح اعتماد |
|---|---|---|
| **بیلد محلیِ موفق** | یک ISO که خودتان از یک commit مشخص ساخته‌اید | بالاترین — شما همهٔ مراحل را کنترل کرده‌اید، اما باید خودتان آن را راستی‌آزمایی کنید |
| **مصنوعِ CI** | یک ISO به‌همراه `.iso.sha256` که توسط یک اجرای موفق workflow بارگذاری شده است | وابسته به یک commit مشخص؛ مناسب برای آزمایش؛ یک انتشار رسمی نیست |
| **داراییِ GitHub release** | ISO به‌همراه checksum که توسط `release.yml` به یک انتشار منتشرشدهٔ GitHub پیوست می‌شود | کانال توزیع رسمی پروژه |

فقط سطح سوم باید به کاربران نهایی به‌عنوان تصویر رسمی Yaran Linux
ارائه شود. مصنوع‌های CI تاریخ انقضا دارند (به‌طور پیش‌فرض GitHub
مصنوع‌های workflow را تا ۹۰ روز نگه می‌دارد) و برای آزمایش و بررسی در نظر
گرفته شده‌اند.

## نحوهٔ کار بیلدهای CI

[workflow ساخت و اعتبارسنجی (Build & Validate)](https://github.com/ahb1390/Yaran_linux/actions/workflows/build.yml)
در موارد زیر اجرا می‌شود:

- pushها و pull requestهایی که manifestها، `build.py`، hookها، اسکریپت‌ها،
  تست‌ها، نمونه‌ها (examples)، دارایی‌ها (assets)، مستندات یا workflowها را
  لمس می‌کنند (هدف، شاخهٔ `main` است)،
- اجرای دستی `workflow_dispatch` از تب Actions (به این روش است که بیلدهای
  شاخهٔ `rebrand/yaran-linux` آغاز می‌شوند).

این workflow دو مرحله دارد:

1. **`validate`** — تست‌های واحد، اجرای `--validate` روی هر manifest، و
   اجرای `bash -n` روی هر اسکریپت shell. اگر این مرحله شکست بخورد، هیچ
   تصویری ساخته نمی‌شود.
2. **بیلدهای نسخه‌ها (Editions)** — نسخه‌های Minimal و Extended (هر دو روی
   `ubuntu-latest`)، ARM64 (روی runner بومی `ubuntu-24.04-arm`)، و Server؛
   هر کدام در یک container ممتاز (privileged) از جنس `debian:trixie` که
   اسکریپت `scripts/ci-build.sh` را اجرا می‌کند.

هر job مربوط به هر نسخه، این موارد را بارگذاری (upload) می‌کند:

- `<artifact>-log` — گزارش کامل بیلد، که **حتی وقتی بیلد شکست بخورد هم
  بارگذاری می‌شود** (هنگام عیب‌یابی اول این را دانلود کنید)؛
- `<artifact>` — در صورت موفقیت، فایل‌های `output/*.iso` و `output/*.sha256`
  (`compression-level: 0`، بنابراین ISO بدون فشرده‌سازی مجدد ذخیره می‌شود).

نام مصنوع‌ها: `yaran-amd64-minimal`، `yaran-amd64-extended`،
`yaran-arm64`، `yaran-server-amd64` (هر کدام با یک مصنوعِ هم‌نام با پسوند
`-log`).

## نحوهٔ کار انتشارها (ریلیزها)

[workflow ساخت انتشار (Release Build)](https://github.com/ahb1390/Yaran_linux/actions/workflows/release.yml)
وقتی یک GitHub release **منتشر (publish) می‌شود** فعال می‌شود. این workflow
همهٔ چهار نسخه را با همان job مربوط به `image.yml` می‌سازد و از آنجا که
`release: true` است، هر job فایل‌های `output/*.iso` و `output/*.sha256` خود
را از طریق `softprops/action-gh-release` با `fail_on_unmatched_files: true`
به release پیوست می‌کند — اگر بیلدی ISO تولید نکند، job مربوط به release
به‌جای انتشار یک release ناقص، با شکست مواجه می‌شود.

workflow انتشار از روی commitی که tag مربوط به release به آن اشاره می‌کند
می‌سازد؛ بنابراین ISOها دقیقاً با همان کدِ منبعِ tag‌شده مطابقت دارند.

## انتشار یک نسخه (برای نگه‌دارندگان)

1. مطمئن شوید شاخهٔ `rebrand/yaran-linux` (یا شاخهٔ هدف) سبز است: آخرین اجرای
   workflow ساخت باید برای هر چهار نسخه با موفقیت تمام شده باشد.
2. رشتهٔ نسخه (version) را تعیین کنید. نسخهٔ درج‌شده در manifestها
   (`version`، `iso_filename`، `os_release`) باید با tag مورد نظر
   مطابقت داشته باشد — اگر متفاوت است، ابتدا در یک pull request آن‌ها را
   به‌روزرسانی کنید.
3. یک GitHub release با tag‌ای مانند `v2.0.1` بسازید و آن را **منتشر
   (publish) کنید**. releaseهای پیش‌نویس (Draft) workflow را فعال نمی‌کنند.
4. صبر کنید اجرای Release Build تمام شود، سپس راستی‌آزمایی کنید که هر چهار
   جفت ISO/checksum به release پیوست شده‌اند.
5. یک checksum را گزینشی راستی‌آزمایی کنید (در ادامه) و در صورت امکان، پیش
   از اعلام release، یک ISO را در یک ماشین مجازی بوت کنید.

## دانلود و راستی‌آزمایی مصنوع‌ها

**دارایی‌های release (Release assets)** در صفحهٔ release قرار دارند.
**مصنوع‌های CI** به حساب GitHub نیاز دارند و از صفحهٔ اجرای workflow
دانلود می‌شوند (`Actions` → انتخاب اجرا → اسکرول تا بخش *Artifacts*).

ISO دانلودشده را با فایل checksum آن راستی‌آزمایی کنید:

```bash
sha256sum -c Yaran-2.0-amd64-minimal.iso.sha256
```

فایل checksum شامل مقدار SHA-256 و نام فایل ISO در قالب `sha256sum` است.
برای اینکه یک مصنوع را به منشأ آن گره بزنید، SHA مربوط به commit در اجرای
workflow (که در بالای صفحهٔ اجرا نمایش داده می‌شود) را با خروجی
`git rev-parse HEAD` در checkout خود مقایسه کنید، یا همان commit را به‌صورت
محلی بسازید و checksumهای ISO را مقایسه کنید — با این توجه که محتوای
مخزن و timestampها pin نمی‌شوند؛ بنابراین حتی دو بیلد از یک commit هم
لازم نیست بایت‌به‌بایت یکسان باشند.

## وضعیت

در حال حاضر هر چهار نسخه با موفقیت در CI ساخته می‌شوند. هنوز هیچ GitHub
release منتشر نشده است؛ تا زمانی که این اتفاق بیفتد، مصنوع‌های CI را
به‌عنوان بیلدهای موجودِ پیش از انتشار در نظر بگیرید.
